1. Visão Geral da Arquitetura overview

Extracao2 é um sistema de pré‑processamento contábil construído sobre:

  • Backend: Django 5.1 (LTS) – python manage.py runserver local; Vercel Functions (Python) em produção.
  • Banco de dados: PostgreSQL hospedado no Neon (branch vercel-dev p/ preview, production p/ prod). Driver psycopg v3.
  • Armazenamento de arquivos: Supabase Storage (bucket Via.extracao) via django‑storages (S3‑compatível).
  • LLM: NVIDIA API (endpoint OpenAI‑compatível https://integrate.api.nvidia.com/v1)  – Texto: nvidia/nemotron-3-ultra-550b-a55b  – Visão: meta/llama-3.2-90b-vision-instruct  – Ollama apenas em desenvolvimento local.
  • Frontend: Django Templates + Bootstrap 5.3 + Chart.js (gráficos).
  • Autenticação: Custom User Model usuarios.Usuario (AUTH_USER_MODEL).
  • Testes: pytest‑django + mocks (sem chamadas reais de rede).

3. Fluxos de Execução flows

3.1 Upload de Documento

  1. Usuário acessa /documentos/novo/ → DocumentoCreateView.
  2. Arquivo enviado → armazenado no Supabase Storage (via storage backend).
  3. Registro Documento criado (status PENDENTE).

3.2 Extração (POST /documentos/[pk]/extrair/)

  1. extrair_dados(documento_id) em llm_service/services.py.
  2. Pré‑processamento – escolha do Preprocessor conforme formato_arquivo (PDF, Imagem, XML).
  3. Prompt – template prompts/{tipo}.txt.
  4. Chamada LLM – provider_factory.get_llm_provider() retorna APIProvider (NVIDIA) ou OllamaProvider.
  5. Validação de schema – Pydantic (validacao_schema.validate_extraction) + retry (máx 2).
  6. Conversão monetária – convert_monetary_fields (Decimal → string).
  7. Persistência – cria DadosExtraidos (JSONField + metadados LLM).

3.3 Validação Humana

  1. Lista em /validacao/ (ValidacaoQueueView).
  2. Detalhe lado‑a‑lado em /validacao/[pk]/ (ValidacaoDetailView) – preview do arquivo + campos editáveis.
  3. Ação Aprovar → cria LancamentoPreparado (obrigatórios: documento, origem, data).
  4. Ação Rejeitar → registra ValidacaoLog com decisão.

3.4 Exportação CSV

/dashboard/exportar-csv/ (ExportCSVView) – exporta apenas lançamentos com status_exportacao = PENDENTE, marca como EXPORTADO.

6. Deploy & Configuração de Produção deploy

Variáveis de Ambiente (Vercel → Settings → Environment Variables)

LLM_PROVIDER=api
LLM_API_KEY=
LLM_MODEL=nvidia/nemotron-3-ultra-550b-a55b
LLM_BASE_URL=https://integrate.api.nvidia.com/v1
VISION_LLM_MODEL=meta/llama-3.2-90b-vision-instruct
DATABASE_URL=postgresql://... (pooled)
DATABASE_URL_UNPOOLED=postgresql://... (unpooled p/ migrate)
SUPABASE_URL=https://.supabase.co
SUPABASE_SERVICE_ROLE_KEY=
SUPABASE_BUCKET_NAME=Via.extracao
DJANGO_SECRET_KEY=
DJANGO_ALLOWED_HOSTS=.vercel.app

Build Command (vercel.json)

"buildCommand": "python manage.py collectstatic --noinput"

Migrações** rodam **manualmente** com DATABASE_URL_UNPOOLED:

DATABASE_URL_UNPOOLED=... python manage.py migrate

Limitações Conhecidas

  • Timeout Vercel 300 s – extrações longas podem estourar (futuro: maxDuration no vercel.json plano Pro).
  • Chart.js via CDN (cdn.jsdelivr.net) – em redes restritas, baixar local.
  • Supabase exige SERVICE_ROLE_KEY (não anon key).
  • Admin customizado – não usa django.contrib.admin padrão; mudanças em config/admin_site.py + templates/admin/.
  • XML NF‑e – XMLPreprocessor tenta lxml e cai para xml.etree (stdlib).
